== 1. Document Request (Network) ==

I opened the project using Live Server and, in the DevTools "Network" tab, reloaded the page to see what the browser was requesting. The first request that appears is for the document itself, from which I gathered the following details:

Full URL: http://127.0.0.1:5500/index.html
Protocol:    http
Host:         127.0.0.1 (this is my own computer, which is why it’s not a domain name)
Port:         5500 (the default port used by Live Server)
Path:         /index.html
Method:       GET
Status Code:  200 OK

A 200 status code means the server found the page and delivered it without any issues. I then manually entered a path that doesn't exist to see what would happen:

Non-existent path: http://127.0.0.1:5500/promociones.html
Status Code:       404 Not Found

In this case, the server responds, but it indicates that it does not have that file. This helped me understand that a 404 error doesn't mean the server is down; rather, it means the requested resource does not exist.

== 2. Roles of HTML, CSS, and JavaScript ==

I used the same "Rueda Libre" project to illustrate these concepts, moving beyond simple definitions:

HTML represents the structure and content—for instance, the pricing table: which rows and columns exist and what information each one contains.
CSS defines the visual appearance—for example, the brand's color scheme or ensuring the menu is displayed horizontally rather than as a vertical list.
JavaScript handles behavior—for example, validating a reservation form before it is submitted and alerting the user if any information is missing.

If I remove the CSS, the page retains all its content, though it appears plain. If I remove the HTML, nothing remains. That was the easiest way I found to distinguish between them.

== 3. Relative Path Table ==

For this table, what helped me was to always consider the location of the file where I’m writing the link. If I’m inside the `paginas` (pages) folder and want to link to `index.html`, I need to move up one folder—that’s what `../` represents. If both files are in the same folder, the filename alone is sufficient.

Origin                 -> Destination            -> Path Written
index.html             -> index.html            -> index.html
index.html             -> paginas/tarifas.html  -> paginas/tarifas.html
index.html             -> paginas/reservas.html -> paginas/reservas.html
paginas/tarifas.html   -> index.html            -> ../index.html
paginas/tarifas.html   -> paginas/tarifas.html  -> tarifas.html
paginas/tarifas.html   -> paginas/reservas.html -> reservas.html
paginas/reservas.html  -> index.html            -> ../index.html
paginas/reservas.html  -> paginas/tarifas.html  -> tarifas.html
paginas/reservas.html  -> paginas/reservas.html -> reservas.html
paginas/tarifas.html   -> img/logo.png          -> ../img/logo.png

The last case involves the logo. From `tarifas.html`, I need to move out of the `paginas` folder and then into the `img` folder. If I forget the `../`, the image won’t load, and it will appear as a 404 error in the Network tab—making it easy to spot the mistake.
